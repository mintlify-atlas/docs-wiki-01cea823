Apache Fineract centralizes its runtime configuration in `fineract-provider/src/main/resources/application.properties`. Every `fineract.*` key binds to a field in `FineractProperties.java` (in `fineract-core`) via Spring's `@ConfigurationProperties`. All values can be overridden at container or process startup through environment variables (shell-style `UPPER_SNAKE_CASE`), Java system properties (`-Dfineract.key=value`), or Kubernetes/Docker `env:` blocks.

## How Overrides Work

<Steps>
  <Step title="Environment Variable">
    Each property exposes a `${ENV_VAR:default}` placeholder. Set the environment variable in Docker Compose `env_file:`, Kubernetes `env:` stanza, or the host shell before launching the JVM.
  </Step>
  <Step title="Java System Property">
    Pass `-Dfineract.server.port=8080` to the JVM (`JAVA_TOOL_OPTIONS` env var is the easiest way inside a container).
  </Step>
  <Step title="Additional Properties File">
    Mount an additional `application-override.properties` and activate it with `SPRING_PROFILES_ACTIVE=override`.
  </Step>
</Steps>

## Instance Mode

Controls which roles this node fulfills in a distributed Fineract cluster. The Kafka-based setup in `docker-compose-postgresql-kafka.yml` uses this to designate manager vs worker nodes.

| Property | Env Var | Default | Effect |
|---|---|---|---|
| `fineract.mode.read-enabled` | `FINERACT_MODE_READ_ENABLED` | `true` | Accept read (GET) API requests |
| `fineract.mode.write-enabled` | `FINERACT_MODE_WRITE_ENABLED` | `true` | Accept write (POST/PUT) API requests |
| `fineract.mode.batch-worker-enabled` | `FINERACT_MODE_BATCH_WORKER_ENABLED` | `true` | Execute COB/batch worker jobs |
| `fineract.mode.batch-manager-enabled` | `FINERACT_MODE_BATCH_MANAGER_ENABLED` | `true` | Schedule/partition COB/batch jobs |
| `fineract.node-id` | `FINERACT_NODE_ID` | `1` | Unique node identifier in cluster |

## SQL Injection Validation

Fineract ships 8 named patterns in `application.properties` guarding dynamic SQL queries:

| Pattern Index | Name | Protects Against |
|---|---|---|
| 0 | `inject-blind` | Blind boolean injection (`1=1`) |
| 1 | `detect-entry-point` | Entry point detection |
| 2 | `inject-timing` | Time-based injection (SLEEP, pg_sleep) |
| 3 | `detect-backend` | Backend fingerprinting |
| 4 | `detect-column` | Column enumeration (ORDER BY, UNION SELECT) |
| 5 | `detect-out-of-bands` | OOB exfiltration (LOAD_FILE) |
| 6 | `inject-stacked-query` | Stacked queries (`;DROP TABLE`) |
| 7 | `inject-comment` | Comment injection (`--`, `/*`) |

These patterns are assembled into three validation profiles: `main`, `adhoc`, and `column`. All are enabled by default.
