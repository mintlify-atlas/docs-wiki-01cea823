Apache Fineract publishes all external business events as Avro-encoded byte payloads. Every schema lives in the Gradle module `fineract-avro-schemas`, under `fineract-avro-schemas/src/main/avro/`, and is compiled to Java source at build time. There is **no external schema registry** — the schema's fully-qualified class name is embedded in the `MessageV1.dataschema` field so consumers can resolve it from the JAR on the classpath.

## Module Location and Purpose

| Item | Path |
|------|------|
| Module root | `fineract-avro-schemas/` |
| Avro source | `fineract-avro-schemas/src/main/avro/` |
| Build script | `fineract-avro-schemas/build.gradle` |
| BigDecimal template | `fineract-avro-schemas/src/main/resources/avro-templates/bigdecimal.avsc` |
| Generator templates | `fineract-avro-schemas/src/main/resources/avro-generator-templates/` |

<Note>
The module compiles to Java 1.8 source/target compatibility so the generated classes can be embedded in broker plugins and consumers that target Java 8.
</Note>

## Compilation Pipeline

The build uses `com.github.davidmc24.gradle.plugin.avro-base` and a custom `PreprocessAvroSchemasTask`.

<Steps>
  <Step title="Spotless JSON formatting">
    `spotlessJsonApply` runs first, formatting all `*.avsc` files for consistent style.
  </Step>
  <Step title="PreprocessAvroSchemas task">
    The custom `PreprocessAvroSchemasTask` in `build.gradle` walks every `.avsc` file under
    `src/main/avro/`, replaces every `"bigdecimal"` token with the inline JSON from
    `bigdecimal.avsc` (`{ "logicalType": "decimal", "precision": 27, "scale": 8, "type": "bytes" }`),
    and writes preprocessed files to `$buildDir/generated/avro/src/main/avro/`.
  </Step>
  <Step title="GenerateAvroJavaTask (buildJavaSdk)">
    `buildJavaSdk` (type `GenerateAvroJavaTask`) reads preprocessed schemas from
    `$buildDir/generated/avro/src/main/avro/` and emits Java sources into
    `$buildDir/generated/java/src/main/java/`.
  </Step>
  <Step title="compileJava">
    `compileJava` depends on `buildJavaSdk`. Generated source is included in `sourceSets.main.java`.
    Compiler flags: `-parameters -proc:none -Xlint:-options`. ErrorProne is disabled for this module.
  </Step>
</Steps>

## Versioning Strategy

Every schema name carries a **`V1` suffix** (e.g. `LoanAccountDataV1`, `MessageV1`). The Avro namespace mirrors the directory hierarchy: `org.apache.fineract.avro.<domain>.v1`. When a breaking change is needed, a new `V2` schema is added alongside `V1` — old consumers continue reading `V1`, new consumers read `V2`. The `MessageV1.dataschema` field contains the fully qualified record name so consumers can select the correct deserializer.

### MessageV1 — `MessageV1.avsc`

`namespace: org.apache.fineract.avro`

| Field | Type | Description |
|-------|------|-------------|
| `id` | `long` | Database ID of the persisted `ExternalEvent` row |
| `source` | `string` | Unique identifier of the source service |
| `type` | `string` | Business event type, e.g. `LoanApprovedBusinessEvent` |
| `category` | `string` | Domain category, e.g. `LOAN` |
| `createdAt` | `string` | UTC ISO_LOCAL_DATE_TIME, e.g. `2011-12-03T10:15:30` |
| `businessDate` | `string` | ISO_LOCAL_DATE business date |
| `tenantId` | `string` | Tenant identifier, e.g. `default` |
| `idempotencyKey` | `string` | Consumer de-duplication key |
| `dataschema` | `string` | FQN of the payload schema, e.g. `org.apache.fineract.avro.loan.v1.LoanAccountDataV1` |
| `data` | `bytes` | Avro-serialized payload bytes |

### BulkMessagePayloadV1 — `BulkMessagePayloadV1.avsc`

`namespace: org.apache.fineract.avro` — field: `datas: array<BulkMessageItemV1>`

### BulkMessageItemV1 — `BulkMessageItemV1.avsc`

`namespace: org.apache.fineract.avro` — fields: `id (long)`, `type`, `category`, `dataschema`, `data (bytes)`

## Serialization Flow

The `ExternalEventService` class at
`fineract-core/src/main/java/org/apache/fineract/infrastructure/event/external/service/ExternalEventService.java`
is the single entry point for all event serialization.

```
BusinessEvent<T>
  └─► ExternalEventService.postEvent()
        ├─► entityManager.flush()           // ensure DB state is committed
        ├─► BusinessEventSerializerFactory.create(event)
        │     └─► BusinessEventSerializer.toAvroDTO(event)  // domain-specific, returns ByteBufferSerializable
        ├─► DataEnricherProcessor.enrich(avroDto)           // adds customData / originators
        ├─► avroDto.toByteBuffer()                          // Avro binary serialization (no registry call)
        ├─► ByteBufferConverter.convert(buffer)             // ByteBuffer → byte[]
        └─► ExternalEventRepository.save(ExternalEvent)     // persisted to m_external_event
```

For bulk events (`BulkBusinessEvent`), `handleBulkBusinessEvent` iterates each child event,
calls `BulkMessageItemFactory.createBulkMessageItem`, and wraps everything in
`BulkMessagePayloadV1` before serialization.

The `ExternalEventProducer` interface (`ExternalEventProducer.java`) defines
`sendEvents(Map<Long, List<byte[]>> partitions)` — the transport-layer abstraction that
Kafka/ActiveMQ implementations fulfill. `NoopExternalEventProducer` is the default when
no message broker is configured.

## Schema Registry Decision

<Info>
Fineract does **not** use a schema registry (e.g. Confluent Schema Registry). Instead, the
`dataschema` field in `MessageV1` carries the fully-qualified Java class name of the payload
schema (e.g. `org.apache.fineract.avro.loan.v1.LoanAccountDataV1`). Consumers resolve the
`SpecificRecord` class from the `fineract-avro-schemas` JAR on their classpath using
`Class.forName(dataschema)` and call the static `fromByteBuffer(ByteBuffer)` Avro method.
</Info>

## Gotchas and Invariants

<Warning>
All `bigdecimal` type tokens in `.avsc` files are preprocessed to the full `{ "logicalType": "decimal", "precision": 27, "scale": 8, "type": "bytes" }` definition before compilation. Do not put the actual Avro decimal definition inline — always use `"bigdecimal"` as a placeholder so the template can expand it uniformly.
</Warning>

- All schemas use **nullable union types** (`["null", "actualType"]`) with `"default": null` for every optional field. Required fields in envelope schemas (`MessageV1`, `BulkMessageItemV1`) use non-nullable scalar types.
- The `originators` field (type `array<OriginatorDetailsV1>`) appears on `LoanAccountDataV1`, `LoanTransactionDataV1`, `LoanChargeDataV1`, `LoanRepaymentDueDataV1`, `LoanAccountDelinquencyRangeDataV1`, and `WorkingCapitalLoanTransactionDataV1` — it links a loan/transaction to the funding originator chain.
- The `customData` field (type `map<bytes>`) appears on most primary data records, allowing event consumers to extend payloads without schema changes.
- `EnumOptionDataV1` uses `id: long`, while `StringEnumOptionDataV1` uses `id: string` — these are distinct types, not polymorphic.
