Apache Fineract's external event subsystem provides a durable, asynchronous outbound messaging pipeline that serializes every significant business action into an Avro-encoded message and delivers it to either an Apache Kafka topic or an ActiveMQ/JMS destination. Events are persisted in the `m_external_event` table before dispatch so that nothing is lost even if the message broker is temporarily unreachable; a scheduled Spring Batch job then picks them up in batches and forwards them.

### `ExternalEventStatus` Enum

```java
// ExternalEventStatus.java
public enum ExternalEventStatus {
    TO_BE_SENT,  // Persisted, awaiting batch dispatch
    SENT         // Successfully forwarded to broker
}
```

<Note>There is **no FAILED status** in the current enum. Events that cannot be sent remain as `TO_BE_SENT` and will be retried by the next batch execution. Failed serializations throw a `RuntimeException` that bubbles up to the caller.</Note>

### `ExternalEventConfiguration` Entity (`m_external_event_configuration`)

```java
// ExternalEventConfiguration.java
@Entity @Table(name = "m_external_event_configuration")
public class ExternalEventConfiguration {
    @Id @Column(name = "type")
    private String type;       // event class simple name
    @Column(name = "enabled")
    private boolean enabled;   // default false
}
```

Each row in this table controls whether a specific event type is serialized and persisted. The API at `GET /v1/externalevents/configuration` returns all rows; `PUT` updates them in bulk.

## `ExternalEventService`

Located at `fineract-core/.../event/external/service/ExternalEventService.java`.

```java
public void postEvent(BusinessEvent<T> event)
```

**Flow:**
1. Flushes the JPA `EntityManager` so all DB writes are visible.
2. If `event instanceof BulkBusinessEvent` → builds a `BulkMessagePayloadV1` wrapping all child events.
3. Otherwise → resolves a `BusinessEventSerializer` via `BusinessEventSerializerFactory.create(event)`, calls `toAvroDTO(event)`, then `DataEnricherProcessor.enrich(dto)`, serializes to bytes.
4. Calls `ExternalEventIdempotencyKeyGenerator.generate(event)` for a unique key.
5. Constructs `ExternalEvent(type, category, schema, data, idempotencyKey, aggregateRootId)` — status defaults to `TO_BE_SENT`.
6. `ExternalEventRepository.save(externalEvent)`.

---

## Idempotency Key Generation

The default implementation `DefaultExternalEventIdempotencyKeyGenerator` simply returns `UUID.randomUUID().toString()` for every event. To override, provide a Spring bean implementing `ExternalEventIdempotencyKeyGenerator` — Spring will prefer any non-default bean.

## Scheduled Jobs

### `SendAsynchronousEventsTasklet`

File: `fineract-core/.../event/external/jobs/SendAsynchronousEventsTasklet.java`

1. Checks that at least one producer (JMS or Kafka) is enabled via `isDownstreamChannelEnabled()`.
2. Calls `ExternalEventRepository.findByStatusOrderByBusinessDateAscIdAsc(TO_BE_SENT, PageRequest.ofSize(batchSize))` — batch size read from `ConfigurationDomainService.retrieveExternalEventBatchSize()`.
3. Groups events by `aggregateRootId` to form ordered partitions. Null `aggregateRootId` maps to key `-1L`.
4. Each partition is serialized into `MessageV1` bytes via `MessageFactory.createMessage(ExternalEventView)`.
5. `ExternalEventProducer.sendEvents(Map<Long, List<byte[]>>)` dispatches all partitions.
6. `repository.markEventsSent(eventIds, sentAt)` updates status to `SENT` — executed in parallel via `ThreadPoolTaskExecutor` (bean: `EVENT_MARKS_AS_SENT_EXECUTOR_BEAN_NAME`) to avoid the 65,535 SQL parameter limit when using batch partitioning via `fineract.events.external.partition-size`.

### `PurgeExternalEventsTasklet`

File: `fineract-core/.../event/external/jobs/PurgeExternalEventsTasklet.java`

Reads `ConfigurationDomainService.retrieveExternalEventsPurgeDaysCriteria()` to determine the retention window, then calls `repository.deleteOlderEventsWithSentStatus(SENT, cutoffDate)`.

## Kafka Producer

File: `fineract-provider/.../event/external/producer/kafka/KafkaExternalEventProducer.java`

- Active when `fineract.events.external.producer.kafka.enabled=true`.
- Uses `KafkaTemplate<Long, byte[]>` — key serializer: `LongSerializer`, value serializer: `ByteArraySerializer`.
- Kafka key is `aggregateRootId` — ensures ordered delivery per aggregate root.
- Sends all messages as `CompletableFuture` and waits for `allOf` within `kafkaProperties.getTimeoutInSeconds()`.
- Topic configuration bean: `KafkaExternalEventTopicConfig` with `@Conditional(ExternalEventsKafkaTopicAutoCreateCondition.class)`.
- `ExternalEventKafkaConfiguration` provides `externalEventsProducerFactory` and `externalEventsKafkaTemplate` beans.

## JMS/ActiveMQ Producer

File: `fineract-provider/.../event/external/producer/jms/JMSMultiExternalEventProducer.java`

- Active when `fineract.events.external.producer.jms.enabled=true`.
- Uses `producerCount` (default 1) parallel JMS `MessageProducer` objects from a `CachingConnectionFactory`.
- Consistent hashing via `HashingService.consistentHash(aggregateRootId, producerCount)` maps partitions to producers.
- Creates byte messages via `MessageFactory.createByteMessage(bytes)`.
- Sessions are explicitly closed after send to prevent orphan session leaks from `CachingConnectionFactory`.

## Pipeline Data Flow

```mermaid
flowchart TD
    A[Business Service calls\nBusinessEventNotifierService.notify()] --> B[ExternalEventService.postEvent()]
    B --> C{BulkBusinessEvent?}
    C -- Yes --> D[BulkMessageItemFactory\nbuilds BulkMessagePayloadV1]
    C -- No --> E[BusinessEventSerializerFactory\nresolves serializer]
    E --> F[toAvroDTO → DataEnricherProcessor.enrich]
    F --> G[ByteBufferConverter → byte[]]
    D --> H[ExternalEventRepository.save\nstatus=TO_BE_SENT]
    G --> H
    H --> I[(m_external_event DB)]

    I --> J[SendAsynchronousEventsTasklet\nSpring Batch Job]
    J --> K[findByStatusOrderByBusinessDateAscIdAsc\nbatch page]
    K --> L[MessageFactory.createMessage\nwraps in MessageV1]
    L --> M{Producer}
    M -- Kafka --> N[KafkaExternalEventProducer\nsend with aggregateRootId key]
    M -- JMS --> O[JMSMultiExternalEventProducer\nconsistent hash routing]
    N --> P[markEventsSent]
    O --> P
    P --> I

    I --> Q[PurgeExternalEventsTasklet\ndeletes old SENT events]
```

## Gotchas & Invariants

<Warning>
**Both JMS and Kafka can be enabled simultaneously.** `SendAsynchronousEventsTasklet.isDownstreamChannelEnabled()` returns true if *either* is enabled. However, only the active producer bean is wired — a Kafka and JMS producer cannot both be active at the same time in practice because the `@ConditionalOnProperty` guards are mutually exclusive per producer bean.
</Warning>

<Warning>
**Partition size guard for SQL.** When marking events as sent, the code splits event IDs into chunks of `fineract.events.external.partition-size` (default 5000) to avoid hitting the 65,535 PreparedStatement parameter limit on some JDBC drivers.
</Warning>

<Note>
**`aggregateRootId` = null maps to -1L** as the Kafka partition key. All events without an aggregate root (e.g. bulk events) are sent on the same partition, which may be a bottleneck under high load.
</Note>

<Tip>
**Enabling an event type** requires a `PUT /v1/externalevents/configuration` call with `enabled: true` for the specific type name. All types default to `false` in `m_external_event_configuration` on first boot.
</Tip>
