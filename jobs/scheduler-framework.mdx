Fineract's scheduler framework bridges the gap between Quartz cron triggers and Spring Batch job execution. Every named batch job is stored in the `job` database table as a `ScheduledJobDetail` entity, assigned a cron expression and a node affinity, and scheduled into a per-tenant Quartz `Scheduler` instance. Two layers of REST APIs—`SchedulerApiResource` and `SchedulerJobApiResource`—let operators suspend the entire scheduler, manually trigger individual jobs, and update cron expressions without a restart. A third resource, `InlineJobApiResource`, executes jobs synchronously (used by the COB inline path). Job discovery is driven by the `JobName` enum plus the extensible `JobNameProvider` SPI, and Spring Batch's `JobRepository` is given a custom `FineractDataFieldMaxValueIncrementerFactory` so that MariaDB and PostgreSQL primary key sequences work correctly.

## `ScheduledJobDetail` Entity (`job` table)

```java
// fineract-provider/…/jobs/domain/ScheduledJobDetail.java
@Entity @Table(name = "job")
public class ScheduledJobDetail extends AbstractPersistableCustom<Long> {
    @Column(name = "name")              private String jobName;
    @Column(name = "display_name")      private String jobDisplayName;
    @Column(name = "node_id")           private Integer nodeId;
    @Column(name = "is_mismatched_job") private boolean isMismatchedJob;
    @Column(name = "cron_expression")   private String cronExpression;
    @Column(name = "create_time")       private Date createTime;
    @Column(name = "task_priority")     private Short taskPriority;
    @Column(name = "group_name")        private String groupName;
    @Column(name = "previous_run_start_time") private Date previousRunStartTime;
    @Column(name = "next_run_time")     private Date nextRunTime;
    @Column(name = "job_key")           private String jobKey;
    @Column(name = "initializing_errorlog") private String errorLog;
    @Column(name = "is_active")         private boolean activeSchedular;
    @Column(name = "currently_running") private boolean currentlyRunning;
    @Column(name = "updates_allowed")   private boolean updatesAllowed;
    @Column(name = "scheduler_group")   private Short schedulerGroup;
    @Column(name = "is_misfired")       private boolean triggerMisfired;
    @Column(name = "short_name", nullable = false) private String shortName;
}
```

### Field semantics

| Column | Field | Meaning |
|--------|-------|---------|
| `name` | `jobName` | Human-readable name matching `JobName.toString()` |
| `display_name` | `jobDisplayName` | Display name shown in UI (mutable via `PUT /v1/jobs`) |
| `short_name` | `shortName` | Unique slug (e.g. `SA_PINT`); used in the `/short-name/{shortName}` API paths |
| `node_id` | `nodeId` | Cluster node the job is pinned to; `0` means "any node" |
| `is_mismatched_job` | `isMismatchedJob` | Set when `nodeId` doesn't match current `fineract.nodeId`; job is skipped |
| `cron_expression` | `cronExpression` | Quartz cron string, e.g. `0 0 22 * * ?` |
| `next_run_time` | `nextRunTime` | Next scheduled fire time (written after `scheduleJob()`) |
| `previous_run_start_time` | `previousRunStartTime` | Start timestamp of last execution |
| `job_key` | `jobKey` | Quartz `JobKey` serialised as `name:group` |
| `is_active` | `activeSchedular` | Whether the job is enabled (mutable via API) |
| `currently_running` | `currentlyRunning` | Pessimistic guard; set true on start, false on finish |
| `scheduler_group` | `schedulerGroup` | Logical grouping affecting thread pool selection; `0` = default pool |
| `is_misfired` | `triggerMisfired` | True when a Quartz trigger fires after its scheduled time |
| `task_priority` | `taskPriority` | Quartz trigger priority |
| `updates_allowed` | `updatesAllowed` | Whether cron and active-status can be changed via the API |

## `ScheduledJobRunHistory` Entity (`job_run_history` table)

```java
// fineract-provider/…/jobs/domain/ScheduledJobRunHistory.java
@Entity @Table(name = "job_run_history")
public class ScheduledJobRunHistory extends AbstractPersistableCustom<Long> {
    @ManyToOne @JoinColumn(name = "job_id")
    private ScheduledJobDetail scheduledJobDetail;
    @Column(name = "version")        private Long version;
    @Column(name = "start_time")     private Date startTime;
    @Column(name = "end_time")       private Date endTime;
    @Column(name = "status")         private String status;
    @Column(name = "error_message")  private String errorMessage;
    @Column(name = "trigger_type")   private String triggerType;
    @Column(name = "error_log")      private String errorLog;
}
```

`triggerType` is a string constant from `SchedulerServiceConstants`: `cron` or `application` (manual). `ScheduledJobRunHistoryRepository.findMaxVersionByJobKey(String jobKey)` is used to determine the next sequential version number.

## REST API Reference

### `SchedulerApiResource` — `/v1/scheduler`

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/v1/scheduler` | `READ_SCHEDULER` | Returns `{ "active": true/false }` |
| `POST` | `/v1/scheduler?command=start` | `UPDATE_SCHEDULER` or `ALL_FUNCTIONS` | Resumes all cron triggers; replays any misfired jobs |
| `POST` | `/v1/scheduler?command=stop` | `UPDATE_SCHEDULER` or `ALL_FUNCTIONS` | Suspends all cron triggers |

The in-memory state is stored via `SchedulerDetailRepository` → `SchedulerDetail` (table `c_scheduler_detail`, column `is_suspended`). When the scheduler is resumed and `executeInstructionForMisfiredJobs` is `true`, every job with `triggerMisfired=true` and `activeSchedular=true` is immediately re-executed.

### `SchedulerJobApiResource` — `/v1/jobs`

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/jobs` | List all jobs (returns `JobDetailData[]` including last run history) |
| `GET` | `/v1/jobs/{jobId}` | Get a job by numeric ID |
| `GET` | `/v1/jobs/short-name/{shortName}` | Get a job by its `shortName` slug |
| `GET` | `/v1/jobs/{jobId}/runhistory` | Paginated run history (params: `offset`, `limit`, `orderBy`, `sortOrder`) |
| `GET` | `/v1/jobs/short-name/{shortName}/runhistory` | Same by short name |
| `POST` | `/v1/jobs/{jobId}?command=executeJob` | Asynchronously trigger job; requires `EXECUTEJOB_SCHEDULER` or `ALL_FUNCTIONS`; only allowed on batch-manager nodes (`fineract.mode.batch-manager-enabled=true`) |
| `POST` | `/v1/jobs/short-name/{shortName}?command=executeJob` | Same by short name |
| `PUT` | `/v1/jobs/{jobId}` | Update `displayName`, `cronExpression`, `active`; triggers `rescheduleJob` if cron or active changes |
| `PUT` | `/v1/jobs/short-name/{shortName}` | Same by short name |

Command execution flows through `ExecuteJobCommandHandler` → `JobRegisterServiceImpl.executeJobWithParameters(jobId, paramsJson)`.

### `InlineJobApiResource` — `/v1/jobs/{jobName}/inline`

```
POST /v1/jobs/{jobName}/inline
Content-Type: application/json
{ "loanIds": [1, 2, 3] }
```

Routes through `CommandWrapperBuilder.executeInlineJob(jobName)` → `InlineJobExecuteHandler` → `InlineJobType.getInlineJobType(jobName)` → the appropriate `InlineExecutorService` implementation. Currently supported job names:

| `jobName` path param | `InlineJobType` | Executor class |
|---------------------|-----------------|----------------|
| `LOAN_COB` | `InlineJobType.LOAN_COB` | `InlineLoanCOBExecutorServiceImpl` |
| `WC_LOAN_COB` | `InlineJobType.WC_LOAN_COB` | `InlineWorkingCapitalLoanCOBExecutorServiceImpl` |

## Job Discovery: `JobNameProviderConfig` and `JobNameService`

```java
// fineract-provider/…/jobs/config/JobNameProviderConfig.java
@Bean
public JobNameProvider fineractJobNameProvider() {
    List<JobNameData> jobNames = Arrays.stream(JobName.values())
        .map(jn -> new JobNameData(jn.name(), jn.toString()))
        .toList();
    return new SimpleJobNameProvider(jobNames);
}
```

`JobNameService` aggregates all `JobNameProvider` beans. When `JobRegisterServiceImpl.createJobDetail()` fires, it calls `jobNameService.getJobByHumanReadableName(scheduledJobDetail.getJobName())` to map the human-readable name stored in the `job` table back to the Spring Batch `Job` bean name (the enum constant name, e.g. `LOAN_COB`). Plugins can register additional `JobNameProvider` beans to add custom jobs.

## `FineractDataFieldMaxValueIncrementerFactory`

```java
// fineract-provider/…/jobs/config/FineractDataFieldMaxValueIncrementerFactory.java
public class FineractDataFieldMaxValueIncrementerFactory implements DataFieldMaxValueIncrementerFactory {
    // Supported: MARIADB, MYSQL, POSTGRES
    // MySQL/MariaDB → MySQLMaxValueIncrementer (useNewConnection=true)
    // Postgres      → PostgresSequenceMaxValueIncrementer
}
```

<Note>
Spring 6 introduced a new MariaDB incrementer incompatible with Spring Batch 4.x's `DefaultDataFieldMaxValueIncrementerFactory`. This custom factory overrides that factory to avoid the incompatibility. It is registered as a bean in `ScheduledJobRunnerConfig` and injected into `JobRepositoryFactoryBean`.
</Note>

## `ScheduledJobRunnerConfig` — Spring Batch Infrastructure

```java
// fineract-provider/…/jobs/ScheduledJobRunnerConfig.java
@Configuration @EnableBatchProcessing
public class ScheduledJobRunnerConfig {
    // JobRepository: isolation=READ_COMMITTED, Jackson2ExecutionContextStringSerializer
    // JobExplorer: same DataSource + TransactionManager
    // TaskExecutorJobLauncher: synchronous (default TaskExecutor)
}
```

Both `JobRepository` and `JobExplorer` use the `RoutingDataSource` (tenant-aware) and the `batchJdbcTransactionManager` qualifier. `Jackson2ExecutionContextStringSerializer` replaces Java serialization for step execution contexts.

## How Jobs Are Triggered

```mermaid
flowchart TD
    A[Quartz cron trigger fires] --> B[JobRegisterServiceImpl.executeJob]
    C[POST /v1/jobs/{id}?command=executeJob] --> D[ExecuteJobCommandHandler]
    D --> B
    E[POST /v1/jobs/{jobName}/inline] --> F[InlineJobExecuteHandler]
    F --> G[InlineExecutorService.executeInlineJob]
    B --> H[Quartz Scheduler.triggerJob]
    H --> I[SchedulerJobListener.jobToBeExecuted]
    I --> J[JobStarter.run]
    J --> K[Spring Batch JobLauncher.run]
    K --> L[Spring Batch Job execution]
```

## `JobRegisterServiceImpl` Key Mechanics

- **Multi-tenant schedulers**: One Quartz `Scheduler` per tenant per scheduler group, keyed by `"scheduler" + tenantId` (or `+ "group" + schedulerGroup` for group > 0). Stored in a static `HashMap<String, Scheduler> SCHEDULERS`.
- **Thread pools**: Default pool uses `SchedulerServiceConstants.DEFAULT_THREAD_COUNT` threads; group > 0 uses `GROUP_THREAD_COUNT`.
- **Misfire replay**: On `startScheduler()`, if `executeInstructionForMisfiredJobs=true`, all `triggerMisfired=true` active jobs are re-fired immediately.
- **Node affinity**: If `scheduledJobDetail.nodeId` doesn't match `fineract.nodeId` and isn't `0`, a `JobNodeIdMismatchingException` is thrown and the job is flagged `isMismatchedJob=true`.
- **Shutdown**: Listens to `ContextClosedEvent` to call `stopAllSchedulers()`.

## Gotchas & Invariants

<Warning>
`currentlyRunning` is a database flag, not an in-memory lock. In a multi-node cluster, two nodes may both see `currentlyRunning=false` and execute the same job simultaneously unless `nodeId` partitioning is configured correctly.
</Warning>

<Warning>
`JobRegisterServiceImpl` uses a static `HashMap SCHEDULERS` to store Quartz scheduler instances. This means scheduler state is not serialized or shared across JVM restarts or cluster nodes.
</Warning>

- `InlineJobApiResource` does **not** check `batch-manager-enabled`; it routes to the inline executor which runs in the current thread.
- The `short_name` column has a unique constraint (`job_short_name_key`). Attempting to register two jobs with the same short name will fail at DB level.
- `ScheduledJobRunHistory.version` is a monotonic integer per `jobKey`, incremented via `findMaxVersionByJobKey` before each insert.
- Changing `cronExpression` or `active` via `PUT /v1/jobs/{id}` triggers `jobRegisterService.rescheduleJob(jobId)` which deletes the old Quartz job and re-schedules it.
- `SchedulerJobApiConstants.COMMAND_EXECUTE_JOB = "executeJob"` — other values throw `UnrecognizedQueryParamException`.
