Loan products in Apache Fineract serve as blueprints for individual loan accounts. Every `Loan` embeds a reference to a `LoanProduct` (`m_product_loan`) and, at creation time, copies the product's `LoanProductRelatedDetail` into its own `loanRepaymentScheduleDetail` embedded object. This copy-on-create design means product changes do not retroactively alter existing loans; only the product's `m_product_loan` row changes. The product controls interest method, amortisation, repayment frequency, grace periods, days-in-year convention, fee and penalty charges, accounting rule type, GL account mappings, and — for progressive-loan products — payment allocation rules.

## LoanProductBorrowerCycleVariations

Entity: `fineract-loan/.../loanproduct/domain/LoanProductBorrowerCycleVariations.java`. Table: `m_product_loan_variations_borrower_cycle`.

This entity stores per-cycle overrides for three parameters: `principal`, `interestRate`, and `numberOfRepayments`. Each row has:

| Field | Column | Description |
|---|---|---|
| `loanProduct` | `loan_product_id` | Parent product |
| `borrowerCycleNumber` | `borrower_cycle_number` | The cycle this row applies to |
| `paramType` | `param_type` | `LoanProductParamType` int code (PRINCIPAL=1, INTERESTRATE=2, REPAYMENT=3) |
| `valueConditionType` | `value_condition` | `LoanProductValueConditionType` (EQUAL=1, GREATERTHAN=2) |
| `minValue` | `min_value` | Minimum override |
| `maxValue` | `max_value` | Maximum override |
| `defaultValue` | `default_value` | Default override |

When `LoanProduct.useBorrowerCycle = true`, the assembler selects the matching row from `borrowerCycleVariations` based on how many previous loans this client has had with this product.

## LoanProductDataValidator

Class: `fineract-provider/.../loanproduct/serialization/LoanProductDataValidator.java`.

<Steps>
  <Step title="Parse JSON">
    Converts the request body to a `JsonElement` and checks it is not empty — throws `InvalidJsonException` if blank.
  </Step>
  <Step title="Validate base fields">
    Uses `DataValidatorBuilder` to assert required fields (`name`, `shortName`, `currencyCode`, `digitsAfterDecimal`, `principal`, `interestRatePerPeriod`, `numberOfRepayments`, `repaymentEvery`, `repaymentFrequencyType`, `interestType`, `amortizationType`, `loanScheduleType`) and that rates are within bounds.
  </Step>
  <Step title="Validate equal-amortization constraints">
    If `isEqualAmortization = true`, rejects combinations with interest recalculation, floating rates, variable installments, and tranche disbursal — throws `EqualAmortizationUnsupportedFeatureException`.
  </Step>
  <Step title="Validate Progressive schedule constraints">
    If `loanScheduleType = PROGRESSIVE`, enforces that `fixedLength` is only used with zero-interest or advanced payment allocation strategies.
  </Step>
  <Step title="Throw accumulated errors">
    `throwExceptionIfValidationWarningsExist(dataValidationErrors)` throws `PlatformApiDataValidationException` if any errors exist.
  </Step>
</Steps>

## ProductToGLAccountMapping

Loan products link to GL accounts via `m_product_to_gl_account_mapping`. The `AccountingRuleType` on the product governs which accounts are required:

| Accounting Rule | Required GL Account Types |
|---|---|
| `NONE` (1) | None |
| `CASH_BASED` (2) | Fund Source, Loan Portfolio, Income from Interest, Income from Fees, Losses |
| `ACCRUAL_PERIODIC` (3) | All cash accounts + Accrual accounts (Interest Receivable, Fee Receivable) |
| `ACCRUAL_UPFRONT` (4) | All accrual accounts + Deferred Income accounts |

## Gotchas & Invariants

<Warning>
`LoanProductRelatedDetail` is `@Embeddable` and shared between `LoanProduct` and `Loan`. Changes to the product's embedded detail **do not** cascade to existing loan accounts — each loan holds its own copy of the detail from the time of creation.
</Warning>

<Warning>
`AmortizationMethod.EQUAL_INSTALLMENTS` (value=1) and `EQUAL_PRINCIPAL` (value=0) are stored using `EnumType.ORDINAL` (not string). If enum values are ever reordered in source code, existing data breaks silently. Do not reorder.
</Warning>

<Note>
When `isLinkedToFloatingInterestRate = true`, the interest rate is derived at runtime from `LoanProductFloatingRates` rather than from `nominalInterestRatePerPeriod`. The `LoanProductDataValidator` rejects floating rates combined with equal-amortization.
</Note>

<Note>
The `loanScheduleType` field is stored as a `STRING` enum in `loan_schedule_type` column. `CUMULATIVE` is the legacy model; `PROGRESSIVE` enables advanced payment allocation rules (`LoanProductPaymentAllocationRule`) and credit allocation rules (`LoanProductCreditAllocationRule`).
</Note>
