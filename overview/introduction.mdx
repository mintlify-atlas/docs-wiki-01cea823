Apache Fineract is an open-source, production-grade **core banking platform** built on Java 21 and Spring Boot 3.x. It provides the infrastructure that financial institutions, fintech startups, and microfinance organizations need to manage loans, savings, accounting, and the full client lifecycle — without starting from scratch. Maintained under the Apache Software Foundation, it is a verified Digital Public Good and powers real deployments on every inhabited continent.

## What Apache Fineract Is

Fineract exposes a **REST API only** — it ships no UI of its own. Clients (web apps, mobile apps, third-party systems) call its `https://<host>:8443/fineract-provider/api/v1/...` endpoints. Every write operation passes through a **CQRS command bus** (`CommandDispatcher` → `CommandHandler`) that records an immutable audit trail, supports maker-checker four-eyes approval, and provides Resilience4j-based retry logic. Close-of-Business (COB) processing uses Spring Batch partitioning to handle millions of loans nightly.

The canonical entry-point class is `org.apache.fineract.ServerApplication` in `fineract-provider/src/main/java/org/apache/fineract/ServerApplication.java`. It extends `SpringBootServletInitializer` so the same binary can run as a **self-contained Spring Boot JAR** (recommended) or be deployed as a **WAR** to an external Tomcat ≥ 10.

## System Requirements

| Requirement | Minimum | Recommended / Tested |
|---|---|---|
| **JVM** | Java 21 | Azul Zulu JDK 21 (CI-tested) |
| **Database** | PostgreSQL 18.0 | PostgreSQL 18.3 (Docker: `postgres:18.3`) |
| **RAM** | 16 GB | 16 GB+ for production |
| **CPU** | 8 cores | 8+ cores |
| **Tomcat** (WAR only) | v10 | Not needed for JAR deployment |

<Warning>
MySQL and MariaDB are **deprecated** as of FSIP-9. Their JDBC drivers are excluded from all distributed artifacts due to GPL/LGPL license incompatibilities. PostgreSQL is the only officially supported and tested database.
</Warning>

## Deployment Models

<Tabs>
  <Tab title="Self-Contained JAR (Recommended)">
    Build and run a Spring Boot fat-JAR with an embedded Tomcat:

    ```bash
    ./gradlew clean bootJar
    # Output: fineract-provider/build/libs/fineract-provider-<version>.jar

    java -jar fineract-provider/build/libs/fineract-provider.jar
    ```

    The server listens on `https://localhost:8443/fineract-provider/` by default. SSL is enabled by default using a self-signed `keystore.jks` bundled in `fineract-provider/src/main/resources/keystore.jks`.
  </Tab>
  <Tab title="WAR Deployment">
    Build and deploy to an external Tomcat 10+:

    ```bash
    ./gradlew :fineract-war:clean :fineract-war:war
    # Output: fineract-war/build/libs/fineract-war-<version>.war
    ```

    Copy the WAR to your Tomcat `webapps/` directory. The `fineract-war` module is a thin wrapper with no additional logic.
  </Tab>
  <Tab title="Docker / Docker Compose">
    ```bash
    # Build image with Jib (no Docker daemon needed)
    ./gradlew :fineract-provider:jibDockerBuild -x test

    # Start full stack (Fineract + PostgreSQL + Grafana/Loki)
    docker compose -f docker-compose-development.yml up -d
    ```

    The official image is `apache/fineract` on Docker Hub. It ships only the PostgreSQL JDBC driver.
  </Tab>
  <Tab title="Quick Local Dev">
    ```bash
    # Prerequisite: PostgreSQL running on localhost:5432

    ./gradlew createPGDB -PdbName=fineract_tenants
    ./gradlew createPGDB -PdbName=fineract_default
    ./gradlew devRun
    # API available at https://localhost:8443/fineract-provider/
    ```
  </Tab>
</Tabs>

## Primary Entry Points

### `ServerApplication.java`

**File:** `fineract-provider/src/main/java/org/apache/fineract/ServerApplication.java`

```java
public class ServerApplication extends SpringBootServletInitializer {

    @Import({ FineractWebApplicationConfiguration.class,
              FineractLiquibaseOnlyApplicationConfiguration.class })
    private static final class Configuration {}

    public static void main(String[] args) throws IOException {
        configureApplication(new SpringApplicationBuilder(ServerApplication.class)).run(args);
    }
}
```

`ServerApplication` performs two actions:
1. **JAR path:** `main()` calls `configureApplication()`, which passes the inner `Configuration` class to `SpringApplicationBuilder`. Spring Boot then loads all auto-configurations filtered by `FineractWebApplicationConfiguration`.
2. **WAR path:** `configure(SpringApplicationBuilder)` is called by the servlet container initializer; it routes to the same `configureApplication()` method.

The inner `Configuration` class uses `@Import` to pull in:
- `FineractWebApplicationConfiguration` — the primary Spring config (see below).
- `FineractLiquibaseOnlyApplicationConfiguration` — a secondary configuration that runs Liquibase tenant database migrations independently.

### `FineractWebApplicationConfiguration.java`

**File:** `fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/boot/FineractWebApplicationConfiguration.java`

This is the **root Spring configuration** class. Key annotations:

| Annotation | Effect |
|---|---|
| `@EnableAutoConfiguration(exclude = {...})` | Disables Spring Boot auto-configuration for DataSource, JPA, Liquibase, Gson, JdbcTemplate — Fineract wires these manually |
| `@EnableTransactionManagement` | Activates `@Transactional` AOP proxy weaving |
| `@EnableWebSecurity` | Activates Spring Security filter chain |
| `@EnableConfigurationProperties({ FineractProperties.class, LiquibaseProperties.class })` | Binds `application.properties` to `FineractProperties` |
| `@ComponentScan(basePackages = "org.apache.fineract.**")` | Discovers all beans across **all** fineract modules on the classpath |
| `@IntegrationComponentScan(basePackages = "org.apache.fineract.**")` | Scans Spring Integration components |
| `@Conditional(FineractWebApplicationCondition.class)` | Activates only in full web application mode (not standalone Liquibase runs) |

## Key Design Principles

<CardGroup cols={2}>
  <Card title="Multi-Tenancy" icon="building">
    A single JVM process serves multiple independent tenants. Every HTTP request carries `Fineract-Platform-TenantId` header. The `TenantAwareBasicAuthenticationFilter` reads this header, resolves tenant details from the `fineract_tenants` meta-database, and stores the `FineractPlatformTenant` in `ThreadLocalContextUtil`. The `RoutingDataSource` then routes every JDBC call to the per-tenant HikariCP pool.
  </Card>
  <Card title="CQRS Command Bus" icon="arrow-right-arrow-left">
    Every state-changing operation flows through `PortfolioCommandSourceWritePlatformService.logCommandSource()` → `SynchronousCommandProcessingService.executeCommand()` → `CommandHandlerProvider` lookup → `NewCommandSourceHandler.processCommand()`. The command is persisted (audit trail) before execution.
  </Card>
  <Card title="Spring Batch COB" icon="calendar">
    The Loan Close-of-Business job (`LOAN_COB`) runs nightly via Spring Batch. `CommonPartitioner` splits loans into ID-range partitions. Worker nodes execute `COBBusinessStep` implementations per loan. Partitioned execution can run on multiple JVM nodes via Spring Events (default), ActiveMQ, or Kafka.
  </Card>
  <Card title="Event-Driven" icon="bolt">
    Domain events (e.g., `ClientCreated`, `LoanDisbursed`) are emitted as Avro-serialized messages to JMS or Kafka when `fineract.events.external.enabled=true`. Schema definitions live in `fineract-avro-schemas`.
  </Card>
</CardGroup>

## Verify a Running Instance

```bash
# Health check (no auth required)
curl --insecure https://localhost:8443/fineract-provider/actuator/health
# Expected: {"status":"UP","groups":["liveness","readiness"]}

# Authenticated API call — default tenant, default credentials (mifos:password)
curl --insecure \
  https://localhost:8443/fineract-provider/api/v1/clients \
  --header 'Fineract-Platform-TenantId: default' \
  --header 'Authorization: Basic bWlmb3M6cGFzc3dvcmQ='
# Expected: {"totalFilteredRecords":0,"pageItems":[]}
```

<Tip>
The `Fineract-Platform-TenantId` header is **mandatory** for every authenticated API call. Omitting it returns a `401` with `InvalidTenantIdentifierException`. The default development tenant identifier is `default`, backed by the database `fineract_default`.
</Tip>
