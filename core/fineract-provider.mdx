`fineract-provider` is the executable Spring Boot assembly module. It does not contain domain logic — it imports every domain and infrastructure module, wires them together, and exposes the HTTP API surface. The module contains the `FineractApp` main class, two exclusive `@Configuration` root classes (`FineractWebApplicationConfiguration` and `FineractLiquibaseOnlyApplicationConfiguration`), Jersey/JAX-RS registration, security configuration, provider-level event serializers, and implementations of platform-neutral interfaces declared in `fineract-core`.

<Note>
All JAX-RS resource classes (`@Path`) and JAX-RS providers (`@Provider`) throughout the entire codebase are discovered and registered at startup by `JerseyConfig.setup()` via Spring's `ApplicationContext.getBeansWithAnnotation`. You do **not** need to register a new resource class explicitly — annotate it with `@Component` and `@Path` and it will be picked up automatically.
</Note>

## Boot configuration

### `FineractWebApplicationConfiguration`
**File:** `fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/boot/FineractWebApplicationConfiguration.java`

The primary root configuration activated by `FineractWebApplicationCondition` (checks that the process was **not** started in Liquibase-only mode). It:

- Annotates with `@EnableAutoConfiguration(exclude = { DataSourceAutoConfiguration, HibernateJpaAutoConfiguration, DataSourceTransactionManagerAutoConfiguration, GsonAutoConfiguration, JdbcTemplateAutoConfiguration, LiquibaseAutoConfiguration })` — these are all replaced by manual beans in `fineract-core` and `fineract-provider`.
- Enables `@EnableTransactionManagement`, `@EnableWebSecurity`.
- Activates `@ComponentScan(basePackages = "org.apache.fineract.**")` which picks up every `@Component`, `@Service`, `@Repository`, `@RestController`, `@Path`-annotated class across all included JARs.
- Activates `@IntegrationComponentScan` for Spring Integration gateways.
- Declares `@EnableConfigurationProperties({ FineractProperties.class, LiquibaseProperties.class })`.

### `FineractLiquibaseOnlyApplicationConfiguration`
**File:** `fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/boot/FineractLiquibaseOnlyApplicationConfiguration.java`

Activated by `FineractLiquibaseOnlyApplicationCondition`. Used when the application starts solely to run database migrations (e.g. in a Kubernetes init-container). It imports only:
- `HikariCpConfig` — the master datasource for `fineract_tenants`.
- `JdbcConfig` — the `JdbcTemplate` bean.
- `ComponentScan` restricted to `service/migration`, `service/database`, `service/tenant` packages.

No security, no Jersey, no jobs are wired in this mode.

## Jersey / JAX-RS registration

### `JerseyConfig`
**File:** `fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/jersey/JerseyConfig.java`

```java
@Configuration(proxyBeanMethods = false)
@ApplicationPath("/api")
public class JerseyConfig extends ResourceConfig {
    JerseyConfig() {
        register(MultiPartFeature.class);
        register(new AbstractBinder() {
            protected void configure() {
                bind(PageableParamProvider.class).to(ValueParamProvider.class).in(Singleton.class);
            }
        });
        register(ValidationFeature.class);
        property(ServerProperties.WADL_FEATURE_DISABLE, true);
    }

    @PostConstruct
    public void setup() {
        appCtx.getBeansWithAnnotation(Path.class).values().forEach(this::register);
        appCtx.getBeansWithAnnotation(Provider.class).values().forEach(this::register);
    }
}
```

Key points:
- **Base path** is `/api` — all endpoint URLs are `/api/v1/…`.
- `MultiPartFeature` enables multipart file upload for bulk-import endpoints.
- `PageableParamProvider` lets Jersey inject `Pageable` directly into resource method parameters.
- `ValidationFeature` activates Bean Validation on incoming request bodies.
- WADL is disabled (no `/application.wadl` endpoint).
- The `@PostConstruct setup()` performs reflection-based registration at startup: any bean annotated `@Path` or `@Provider` is registered without explicit listing.

### JSON converters
JAX-RS JSON serialization is handled by custom converters in `fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/jersey/converter/`:
- `LocalDateJsonConverter` — `LocalDate` ↔ ISO-8601 string
- `LocalDateTimeJsonConverter` — `LocalDateTime` ↔ ISO-8601
- `OffsetDateTimeJsonConverter`
- `DateJsonConverter` — legacy `java.util.Date`
- `ExternalIdJsonConverter` — `ExternalId` value type

## Security configuration

### `SecurityConfig`
**File:** `fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/config/SecurityConfig.java`

Wires the Spring Security filter chain. The active security scheme is controlled by `fineract.security.basicauth.enabled` / `fineract.security.oauth2.enabled`. Key filter in the chain:

**`TenantAwareBasicAuthenticationFilter`** (`fineract-security` module):
- Reads `Fineract-Platform-TenantId` header (or falls back to `tenantIdentifier` query param).
- Calls `TenantDetailsService.loadTenantById` to resolve `FineractPlatformTenant`.
- Stores tenant in `ThreadLocalContextUtil`.
- Loads business dates from `BusinessDateReadPlatformService.getBusinessDates()` and stores in thread-local.

## Infrastructure sub-packages (provider-level)

### AdhocQuery
- `AdHocApiResource` at `GET/POST/PUT/DELETE /api/v1/adhocquery` — CRUD for ad-hoc named SQL queries.
- `AdHoc` JPA entity stored in `m_adhoc_query`.
- Queries are executed on a schedule via `RunAdhocReportAndSendMailScheduledJob`.

### Batch API

The Batch API (`POST /api/v1/batches`) allows multiple logical HTTP requests to be submitted as a single HTTP call. It is defined in **fineract-core** (`batch/api/BatchApiResource.java`) and fulfilled via `BatchApiService` with `CommandStrategy` implementations in **fineract-provider**.

<CardGroup cols={2}>
  <Card title="BatchApiResource" icon="layer-group">
    `fineract-core/src/main/java/org/apache/fineract/batch/api/BatchApiResource.java`  
    JAX-RS `@Path("/v1/batches") @POST`. Deserialises an array of `BatchRequest` objects, delegates to `BatchApiService`, returns array of `BatchResponse`.
  </Card>
  <Card title="CommandStrategy" icon="code">
    `fineract-core/src/main/java/org/apache/fineract/batch/command/CommandStrategy.java`  
    `BatchResponse execute(BatchRequest, UriInfo)`. There are **68** `CommandStrategy` implementations in `fineract-provider/src/main/java/org/apache/fineract/batch/command/internal/`.
  </Card>
</CardGroup>

`CommandStrategyProvider` maintains a `ConcurrentHashMap<CommandContext, String>` where `CommandContext` holds the `resource` URL pattern and `method`, and the map value is the Spring bean name of the `CommandStrategy`. It resolves the correct strategy on each batch sub-request by calling `applicationContext.getBean(beanName, CommandStrategy.class)`.

Selected `CommandStrategy` implementations:

| Strategy class | HTTP pattern |
|---|---|
| `ActivateClientCommandStrategy` | `POST /clients/{id}?command=activate` |
| `ApplyLoanCommandStrategy` | `POST /loans` |
| `ApproveLoanCommandStrategy` | `POST /loans/{id}?command=approve` |
| `DisburseLoanCommandStrategy` | `POST /loans/{id}?command=disburse` |
| `RepayLoanCommandStrategy` | `POST /loans/{id}/transactions?command=repayment` |
| `CreateClientCommandStrategy` | `POST /clients` |
| `UpdateClientCommandStrategy` | `PUT /clients/{id}` |
| `SavingsAccountTransactionCommandStrategy` | `POST /savingsaccounts/{id}/transactions` |
| `CollectChargesCommandStrategy` | `GET /loans/{id}/charges` |
| `ModifyLoanApplicationCommandStrategy` | `PUT /loans/{id}` |
| `UnknownCommandStrategy` (core) | fallback — returns `501 Not Implemented` |

JSON Path dependency resolution: if a batch sub-request body or URL contains `$.someField`, the Batch engine substitutes the value from the preceding request's response body using JsonPath expressions.

### Commands / legacy CQRS wiring

Provider-level command handlers live in `fineract-provider/src/main/java/org/apache/fineract/*/handler/`. Each handler implements the legacy `NewCommandSourceHandler` interface (in `fineract-core/commands/`) and is tied to a specific `CommandWrapper.actionName()` + entity type.

`PortfolioCommandSourceWritePlatformServiceImpl` (`fineract-core/src/main/java/org/apache/fineract/commands/service/`) is the legacy entry-point. It calls `CommandProcessingService.executeCommand` which resolves the correct `NewCommandSourceHandler` via Spring context bean lookup, calls `handler.processCommand(command)`, and persists the result in `m_portfolio_command_source`.

## Event producers (provider-level)

### Kafka producer
**File:** `fineract-provider/src/main/java/org/apache/fineract/infrastructure/event/external/config/ExternalEventKafkaConfiguration.java`

Active when `fineract.events.external.producer.kafka.enabled=true`. Registers:
- `ProducerFactory<Long, byte[]>` — `DefaultKafkaProducerFactory` with `LongSerializer` (partition key = aggregate root id) and `ByteArraySerializer` (Avro payload).
- `KafkaTemplate<Long, byte[]> externalEventsKafkaTemplate`.

**`KafkaExternalEventProducer`** (`fineract-provider/…/producer/kafka/KafkaExternalEventProducer.java`) implements `ExternalEventProducer`:
```java
void sendEvents(Map<Long, List<byte[]>> partitions)
```
Sends each `byte[]` payload to topic `fineract.events.external.producer.kafka.topic.name` with the `Long` key as partition key. Waits for acknowledgement up to `fineract.events.external.producer.kafka.timeout-in-seconds`.

### JMS producer (ActiveMQ)
**File:** `fineract-provider/…/producer/jms/JMSMultiExternalEventProducer.java`

Active when `fineract.events.external.producer.jms.enabled=true`. Supports both queue (`event-queue-name`) and topic (`event-topic-name`) destinations. `producer-count` controls concurrency.

### Event serializers
Domain-specific Avro serializers live at `fineract-provider/src/main/java/org/apache/fineract/infrastructure/event/external/service/serialization/serializer/`:
- `loan/LoanBusinessEventSerializer`
- `client/ClientBusinessEventSerializer`
- (savings serializers follow the same pattern)

Each serializer implements `BusinessEventSerializer`:
```java
boolean canSerialize(BusinessEvent<T> event);
Class<? extends GenericContainer> getSupportedSchema();
ByteBufferSerializable toAvroDTO(BusinessEvent<T> rawEvent);
```

`BusinessEventSerializerFactory` iterates all registered serializers, calls `canSerialize`, and returns the first match.

## Key JPA and JDBC configurations

- `HikariCpConfig` (`fineract-provider/…/config/HikariCpConfig.java`) — creates the `hikariTenantDataSource` bean (master `fineract_tenants` pool).
- `JPAConfig` / `JpaTransactionConfig` (`fineract-provider/…/config/jpa/`) — configures the `EntityManagerFactory` with `LocalContainerEntityManagerFactoryBean`. The transaction manager bean name is `jpaTransactionManager`.
- `JdbcTransactionConfig` — configures a separate `DataSourceTransactionManager` for JDBC-only code.
- `CacheConfig` (`fineract-provider/…/config/cache/CacheConfig.java`) — wires `TransactionBoundCacheManager` (clears cache entries on transaction rollback) wrapping `RuntimeDelegatingCacheManager`.

## Gotchas & invariants

<Warning>
`FineractWebApplicationConfiguration` and `FineractLiquibaseOnlyApplicationConfiguration` are mutually exclusive via `@Conditional`. Never include both in the same Spring context. `FineractWebApplicationCondition` returns `false` when `fineract.liquibase-only-mode=true` is set.
</Warning>

<Accordion title="Jersey vs Spring MVC">
Fineract uses Jersey (JAX-RS), not Spring MVC. There is no `@RestController` / `@RequestMapping` anywhere in the API surface. Actuator (`/actuator/**`) is the only path served by Spring MVC's `DispatcherServlet`. Do not mix `@Path` and `@RequestMapping` on the same class.
</Accordion>

<Accordion title="Component scan breadth">
`@ComponentScan(basePackages = "org.apache.fineract.**")` is intentionally broad. It picks up beans from every JAR on the classpath that declares classes in the `org.apache.fineract` hierarchy. Adding a new module to the classpath is sufficient to activate its beans.
</Accordion>

<Accordion title="ContentS3Config auto-wires AWS SDK">
`ContentS3Config` (`fineract-provider/…/config/ContentS3Config.java`) wires the AWS S3 client only when `fineract.content.s3.enabled=true`. If you set this to `true` without valid AWS credentials, the application fails to start.
</Accordion>
